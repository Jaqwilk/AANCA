# Public AANCA deployment inputs

The site's thirteen-file article is built/verified separately under
`artifacts/mvp_demo`. `aancastudy.htaccess` preserves manifest-bound entity bytes
with no-cache/no-transform delivery. Deploy through the owner-controlled Hostinger
tool and retain a recoverable backup; never put credentials in this directory.

The `/review/` guide is generated by `scripts/build_reviewer_kit.py` from the shared
template. Local candidate archives and guide builds are transient QA output.
The configured deployment maps the generated guide HTML as one file and the tracked
`reviewer-snapshot.json` as a separate file to `/review/snapshot.json`.

The tracked snapshot identifies the **published immutable** `reviewer-kit-v1`
download, including its source revision and archive checksum. It must not be
replaced by metadata from a later working-tree build: documentation-only changes
also change a candidate archive's digest, while the published release stays pinned.
Future deploys may rebuild the guide without changing the advertised download.
Publish a new versioned reviewer release before changing this download reference.

The owner-controlled provider manifest lives outside this repository at
`C:\Users\NATAN\Documents\codex-hostinger-deploy\manifests\aancastudy.org.json`.
It builds candidates under `artifacts/qa/reviewer-kit-build`, renders the guide to
`artifacts/qa/reviewer-site-current`, then maps those two explicit guide/reference
files. The article root is merged; unrelated server files are preserved.
